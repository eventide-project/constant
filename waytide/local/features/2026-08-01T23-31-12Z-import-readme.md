# Feature — Import README

## Intent

`README.md` documents `Constant::Import` as it stood before three features added to it. It
is brought current.

**Missing keywords.** The signature is documented in two places — the macro section
(`self.import(origin_constant, alias: nil)`) and the API section
(`self.call(origin_constant, destination_constant, alias: nil)`) — each with its own
parameters table, and both list only `alias`. The current signature is:

```ruby
def self.call(origin_constant, destination_constant, only: nil, except: nil, shadow_inherited: nil, **kwargs)
```

**Missing refusals.** `Constant::Import` refuses five conditions and the README describes
none of them. It documents only the sixth — that including `Constant::Import` at the top
level is refused — which predates this work.

| Condition | Message names |
|---|---|
| The destination already defines the name | the constant, destination, source |
| The destination **inherits** the name | the constant, destination, ancestor, source |
| A name in `only:` is not on the source | the constant, the source |
| A name is in both `only:` and `except:` | the constant |
| A remaining name still collides after either keyword narrows the set | the constant, destination, source |

The README documents raised errors carefully for the `Constant` class — `Constant.get`,
`Constant()`, `Constant::Module#get` all say what they raise and when. `Import` is the
outlier.

## Conclusion

**Completed** — integrated into `master` on Sat Aug 1 2026 at 4:40:11 PM PT. 42 lines added
across the macro and API sections. The library is untouched and the suite holds at **119
tests**.

Both sections carry `only`, `except`, and `shadow_inherited` in the signature, the
parameters table, and prose with examples — following the document's existing habit of
explaining `alias` in both places rather than pointing from one to the other. The raised
conditions are a sentence appended to each `**Returns**` paragraph.

**Two corrections were made during the work rather than carried through it.**

*"Refusals" was not the document's word.* It came from the deferred item that began this line
of work and had been used all session without examination. The README says **raises**;
"refused" appears in it once, for top-level inclusion. The developer's question about the
term is what surfaced it.

*The pattern it implied was checked rather than assumed.* The option presented offered a
`**Raises**` block beside `**Returns**` — and the README has no such block anywhere, raised
errors being a sentence on the end of the `**Returns**` paragraph. Building the block would
have introduced a pattern the document does not use, in the name of matching it.

**The prose was verified against the library**, not written from memory: all ten documented
claims were run, including the two asymmetries the text asserts between `only` and `except`
on a name the source does not own.
